## 2. 每次派单只给"三件套"（调度者照此喂给执行者）

一次只派发**一张任务卡**，并同时提供：

1. **该张任务卡**（`02~05` 中对应 `Txxx` 的整节，自包含）；
2. **`01-技术基线与接口契约.md` 全文**（或该卡"开工前读"列出的小节）；
3. **本 README 全文**。

不要一次给多张卡，不要让执行者"顺便把后面也做了"。

## 3. 执行者十条铁律（强制，逐条遵守）

1. **一次只做一张卡**：只完成该卡声明的文件与行为；不跨卡、不提前实现未派发的功能、不"顺手优化"无关代码。
2. **照规格实现，不自行命名**：文件路径、函数/类型签名、类名、常量、DOM 标记前缀、文案，一律用契约和卡片里给定的；契约未规定的命名，先问。
3. **不擅自引入/更换依赖**：新增任何 npm 依赖必须在卡片明确列出；卡片没列而你认为需要，**停止并上报**，不得自行 `npm install`。所有第三方库只能在 `src/adapters/` 内被 import（见契约 §4）。
4. **先绿后改、改完必验**：动手前先拉取最新代码并跑通基线（`npm run check`）；完成后必须跑通该卡"验收命令"且**全部通过**才算完成。
5. **不许伪造验收**：禁止删除/跳过/弱化测试，禁止修改质量脚本阈值，禁止 `@ts-ignore`/`eslint-disable` 来掩盖错误（确需豁免必须在 PR 说明理由并经评审同意）。
6. **不会就停，不要猜、不要绕**：出现以下任一情况，**立即停止并按 §6 模板上报**，不要继续写：
   - 契约接口与卡片要求对不上；
   - 按步骤做但验收命令失败，自查约 30 分钟仍无法解决；
   - 发现需求自相矛盾、或会破坏已有功能；
   - 卡片要求触碰"明确不做"清单（见 §7）。
7. **一张卡 = 一个分支 = 一个 PR**：分支名 `feat/Txxx-短描述`；提交信息格式 `Txxx: 动词开头的简述`；一个 PR 只包含本卡改动。
8. **编辑器注入物必须可被完全清除**：任何加到被编辑页面上的东西（覆盖层、选中框、临时属性、事件），统一使用 `data-ep-*` 属性 / `.ep__` 类名 / `#ep-overlay-root` 容器（见契约 §6），**严禁**直接改被编辑 DOM 的结构来承载编辑器 UI。
9. **安全红线**：编辑态**绝不执行**导入 HTML 里的 `<script>`；不把用户导入的 HTML/内容发送到任何网络地址（P0 纯本地）。
10. **保持应用随时可运行**：每张卡合入后，`npm run check` 全绿、`npm run dev` 能打开、主流程不出现白屏/崩溃；做不到就不算完成。

## 4. 每张卡的标准完成定义（DoD，逐项打勾）

提交 PR 前，逐条自检（写进 PR 描述的勾选清单）：

- [ ] 只改动了卡片"产出文件"列出的文件（范围外文件零改动，或已在 PR 说明必要原因）。
- [ ] 按契约实现了指定的类型/函数签名，签名与契约逐字一致。
- [ ] `npm run typecheck` 通过（TypeScript strict，0 error）。
- [ ] `npm run lint` 通过（0 error）。
- [ ] `npm run test` 通过；该卡要求新增的测试已写且覆盖"成功 + 失败/边界"两类。
- [ ] `npm run build` 通过。
- [ ] `npm run qa:metrics` 结果**不劣于**该卡之前的基线（命中率/无损率不下降、导出残留为 0）。
- [ ] 完成卡片"手动验收"中的每一步，实际结果与预期一致（在 PR 中贴出截图或文字记录）。
- [ ] 没有引入未批准的依赖；第三方库只出现在 `src/adapters/`。
- [ ] 新增的编辑器注入物全部带 `data-ep-*` / `.ep__` 前缀，且导出 HTML 中**搜不到任何 `ep` 编辑器标记**。
- [ ] 不包含 §7"明确不做"的任何内容。

> 任意一项不满足，**该卡视为未完成**，不得请求评审通过。

## 5. 标准工作循环（每张卡都按此顺序）

1. `git switch main && git pull`，确认 `npm run check` 在本机为绿（不绿先上报，不在脏基线上开工）。
2. 建分支 `git switch -c feat/Txxx-短描述`。
3. 通读任务卡 + 契约相关小节，列出你要新建/修改的文件，确认与卡片一致。
4. 先写/先看测试（卡片给了测试用例就照写），再实现，使测试通过（测试驱动，红绿重构）。
5. 本地跑 `npm run dev`，按卡片"手动验收"操作一遍。
6. 跑全量 §4 的命令；修复至全绿。
7. 提交（可多次小提交），推送，开 PR，PR 描述粘贴 §4 勾选清单与手动验收记录。
8. 按评审意见只修改本卡范围；评审通过后由调度者合并。

常用命令（以契约 §2 最终冻结为准）：

```bash
npm install        # 安装依赖（仅在 T001 之后、且依赖已被批准时）
npm run dev        # 本地启动应用
npm run check      # 一次性执行 typecheck + lint + test + build
npm run typecheck  # 仅类型检查
npm run lint       # 仅 lint
npm run test       # 单元测试（Vitest）
npm run e2e        # 端到端测试（Playwright）
npm run qa:metrics # 样本库质量度量（命中率/无损率/残留率）
npm run build      # 生产构建
```

- 响应式断点的可视化**编辑**（P0 只做多宽度预览）。
- Flex/Grid 结构的可视化重构、从零搭建整站的建站模式。

- 组件市场、模板生态。
- 任何把用户 HTML 上传到服务器的功能。

## 9. 术语统一（避免理解偏差）

- **精修**：对已有 HTML 的可见元素做内容与视觉样式的小幅修改，不重构布局逻辑。
- **文档流位移 vs 视觉位移**：本产品拖拽只产生**视觉位移**（`transform:translate`），元素在文档流中的位置不变；提供"重置位移"。
- **覆盖层（overlay）**：编辑器自己画的选中框、手柄、对齐线、锁遮罩，位于 `#ep-overlay-root`，**不属于被编辑页面**。
- **干净导出**：导出的 HTML 不含任何编辑器注入标记，且未被编辑的部分与导入时保持一致（无损）。
- **行走骨架（Walking Skeleton）**：阶段 1 要先打通的最薄端到端链路：导入 → 改一处文字 → 预览 → 导出干净 HTML，哪怕其他功能都还没有。

## 10. 版本库与回滚点（2026-09-22 补）

仓库此前只有本地文件树、没有 `.git`，铁律 7「一卡一分支一 PR + 回滚 tag」**没有载体**（diff 都出不来）。
现已初始化：分支 `master`，每完成一批可独立回滚的改动即打 tag，命名 `类型-主题-日期`。

| tag | commit | 内容 |
| --- | --- | --- |
| `baseline-20260922` | 80f306e | 审阅基线（未修任何已知偏差的原始状态） |
| `chore-lf-20260922` | e162666 | 统一文本文件行尾为 LF + `.gitattributes`（内容零变化） |
| `feat-fixes-20260922` | c34084c | 草稿续开 / 导入净化接线 / 缩放不再污染撤销栈 |
| `refactor-composition-20260922` | 16148b1 | 装配根回到 `platforms/web`，import 边界真正生效 |

- **行尾约定**：`.gitattributes` 声明 `* text=auto eol=lf`，文本文件一律 LF。
  工具若写入 CRLF，`git diff` 会呈现"整文件重写"的失真 —— 提交前用
  `git diff --ignore-cr-at-eol --numstat` 看真实改动量。
- **度量入库**：`qa/report/` 只保留 `metrics-baseline.json` 与 `metrics-latest.json`，其余按 `.gitignore` 忽略。
  基线必须进版本库，否则「hitRate/losslessRate 不得低于合入前基线」无从比对。
- **禁止 `git rm -r`**：本环境该命令会删掉整个顶层目录树（已复现两次）。删文件只用
  `rm -f <显式文件列表>`，再 `git add -u` 只 stage 已跟踪变更。
- **删除测试/弱化门禁仍属违规**（铁律 5）。仓库有 git 之后，"改完必验"要求附
  `vitest` 与 `playwright` 的实际输出，而不是描述性结论。
