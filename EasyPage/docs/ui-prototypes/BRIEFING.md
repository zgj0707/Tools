# 易页 EasyPage · UI 原型三版 · 共享约束（BRIEFING）

> 本文是三份 UI 原型唯一的事实来源。三份原型由不同执行者产出，方向不同但**区块集合必须一致**，
> 否则无法横向比较。执行者先读完本文再动手。

## 1. 产品与现状（决定原型要解决什么）

- 产品：**易页 EasyPage**，单文件 HTML 精修编辑器。用户导入一份 HTML（落地页 / 活动页 / 邮件 HTML），
  在可视化画布里直接改字、调样式、拖拽缩放、对齐分布，最后导出一份**干净**的 HTML（不含任何编辑器痕迹）。
- 目标用户：运营 / 设计 / 产品，不是前端工程师。他们关心「导出的东西能不能直接用」，而不是会用工具。
- **技术现状（重要）**：项目里**没有任何 CSS 文件**，全部样式是 TypeScript 里的内联 `style` 赋值。
  类名前缀约定 `ep-`（`src/constants.ts` 的 `EP.CLASS_PREFIX`），注释里给的 BEM 示例是 `ep-ribbon__btn--primary`。
- 因此本次原型的目的不是"画好看的图"，而是**为现有功能结构提供三套可落地的视觉方案 + token 表**，
  选型后可以直接把内联样式替换成类名 + CSS 变量。

## 2. 必须呈现的功能区块（三版都要有，位置/形态可不同）

| # | 区块 | 现有实现细节（照抄语义，别丢功能） |
|---|---|---|
| 1 | 一级工具栏 | 导入 HTML、新建空白、预览、导出 HTML、复制 HTML、重置位移、格式刷（双击 = 连续刷） |
| 2 | 对齐 / 分布条 | 左、右、居中、顶、底、垂直居中、水平等距、垂直等距（共 8 个） |
| 3 | 导入区 | 多行文本框（占位文案「在此粘贴 HTML…」）+「选择文件」入口 |
| 4 | 草稿区 | 「最近草稿：<标题> <时间>」+「继续」「删除」；无草稿时显示「无草稿」 |
| 5 | 左侧「插入」面板 | 插入若干控件（文本 / 标题 / 图片 / 按钮 / 容器等）+「删除选中」+「项目符号列表」「编号列表」（已是列表时显示「取消列表」） |
| 6 | 左侧「图层」面板 | 树形行：展开箭头 ▸/▾ · 标签名 · 上移 / 下移 / 置顶 / 置底 四个排序按钮 · 锁定 🔒/🔓 · 隐藏 👁/🚫；底部可能有折叠行「… 显示更多 N 个」 |
| 7 | 编辑画布 | 画布内是被编辑页面（白纸感）；覆盖层含：选中框（2px 实线）、hover 高亮（浅蓝 `rgba(66,133,244,.12)`）、**8 个缩放手柄**（10px 方形，现为橙色系 `rgba(230,81,0,.85)`，白描边）、锁定徽标 |
| 8 | 右侧「样式」面板 | 字体、字号、字重、文字颜色、背景色、对齐、行高、字距、列表（转为列表 / 取消列表）、链接（设置链接 / 清除链接）；多选显示「混合」；元素不可编辑时给出提示态 |
| 9 | 预览态 | 切到预览沙箱（脚本可运行），可切回编辑；画布与预览互斥显示 |
| 10 | 底部面包屑 | 选中元素的祖先路径，可点父级跳选 |
| 11 | toast | 单条文本提示，例：「导入成功」「草稿已保存」「导出成功（含外链资源，离线打开可能失效）」「该元素已锁定」 |
| 12 | 右键菜单 | 删除、复制、重置位移、锁定 / 解锁 |
| 13 | 就地改字态 | 元素进入可编辑态时的视觉表现（光标、编辑中高亮、与其他选中态如何区分） |

## 3. 三版方向（必须区别明显，不接受三版雷同）

| 版本 | 方向 | 参考气质 | 必须做到 |
|---|---|---|---|
| **A · Dark Pro** | 深色高密度工具风 | IDE / Figma 深色 / VS Code | 深色底 + 高信息密度；侧栏窄而紧凑；画布如"白纸浮在暗场"；面板分组用分隔线而非卡片 |
| **B · Light System** | 浅色设计系统风 | 企业级设计系统 | 主色 `#165DFF`、强调色 `#722ED1`；圆角 8–12px；留白舒展；卡片式分区；有完整的 token 表；同时支持深色模式（`prefers-color-scheme` 或右上角切换） |
| **C · Canvas First** | 画布优先的极简沉浸风 | Notion / Canva / Linear | 工具收纳为**浮动词条**（上下文工具栏贴着画布顶部浮动）；左右面板默认收起、按需滑出；弱化边框、大面积留白；界面"存在感最低" |

## 4. 硬约束（违反即返工）

1. **单文件 HTML**，内联 CSS + 最简原生 JS。
2. **零外链**：不得引用 CDN、外部字体、外链图片、外部 JS。产品本身要求纯本地可打开（`file://` 就能跑）。
3. 字体用系统字体栈；图标优先内联 SVG（少量 Unicode 符号可接受，避免把 emoji 当主图标）。
4. 视口：**1440×900 一屏可用**；1280 宽不得横向溢出。
5. 文案用简体中文，尽量复用第 2 节表格里的原文案。
6. 类名以 `ep-` 前缀 + BEM（例：`ep-ribbon__btn--primary`）；**文件顶部注释块必须给出 token 表**
   （颜色 / 间距 / 圆角 / 字号 / 阴影），让实现者能直接抄成 CSS 变量。
7. 演示交互（用最简 JS 即可，别写框架）：至少支持
   ① 点击画布元素 → 出现选中框 + 8 手柄，右侧样式面板进入激活态；
   ② 切换预览态；③ 收起 / 展开左面板；④ 触发一次 toast。
   **不要假装实现真实编辑能力**，原型只表达视觉与交互意图。

## 6. 选型结果与落地（2026-09-22）

**采纳：C · Canvas First（画布优先的极简沉浸风）。**

落地按**两层拆分**推进，因为这两层的代价差一个数量级：

| 层 | 内容 | 状态 |
|---|---|---|
| ① 视觉层 | token 化（颜色/间距/圆角/字号/阴影）、外壳观感、控件外观、选中框统一蓝系 | ✅ 已落地 |
| ② 布局层 | 左右面板默认收起 + 滑出、对齐条改贴画布浮动词条、导入+草稿收进弹层、面包屑改浮动胶囊 | ⏳ 另立一步 |

**为什么拆开**：布局层要改 `App.ts` 的挂载骨架，并直接打垮现有 59 个 e2e
（21 个 spec 里约 157 处断言依赖元素常驻可见）。先把视觉层做完，可保住
「功能已全量验证通过」这个基线，让布局层成为一次可独立回滚的改动。

**落地产物**
- `src/app/style/tokens.css` —— `:root` 变量，全项目唯一设计 token 来源
- `src/app/style/app.css` —— 全项目唯一 CSS 文件，覆盖代码里**早已存在但从未被定义**
  的 `ep-*` 类名（此前项目零 CSS，36 个类名只是空钩子）
- 分工铁律：**CSS 管视觉，JS 内联管几何与行为**。画布尺寸（`width:100%` / `height:600px`）、
  覆盖层坐标、8 手柄尺寸（`HANDLE_SIZE`）一律留在 JS —— 它们是 e2e 几何断言的对象。

**与原型 token 表的有意偏离（1 处）**
原型把 `--ep-selected` / `--ep-handle` 留作橙色 `rgba(230,81,0,*)`（理由「不改辨识度」），
但橙色实际构成第二个强调色，与 C 版「全站只有一个强调色」自相矛盾，故统一并入蓝系
`#2F6BFF`（手柄保留白描边保辨识度）。区分靠形态而非色相：hover 有填充无手柄、
选中无填充有 8 手柄。

**未覆盖项（已知缺口）**
第 13 区块「就地改字态」的**视觉高亮**仍未实现：`[data-ep-editing]` 标记挂在画布
iframe 内的文档上，外壳 CSS 选不到它，需要向 iframe 注入样式；而注入物又必须走
`stripArtifacts` 的干净导出链路，风险独立，故单列待办。
