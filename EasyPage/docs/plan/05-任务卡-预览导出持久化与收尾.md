## T115 · 沙箱预览（iframe 双 DOM，安全版）　🟠 / M

- **目标**：预览态真实运行用户脚本、交互可点、与编辑器外壳强隔离；切回编辑保留改动与撤销历史、恢复滚动；不重建编辑文档。
- **依赖**：T101。
- **开工前读**：`01` §5（双 iframe 矩阵，**预览用 `allow-scripts` 且不给 `allow-same-origin`**）、§4 `PreviewSandbox`、PRD 6.3。
- **关键设计（照此实现，不自行改隔离模型）**：
  - 编辑态 iframe 在预览期间**隐藏但不销毁**，编辑 `doc`、Selection、History 全部保留；预览是另一个独立 iframe。
  - 预览 iframe：`sandbox="allow-scripts"`（**不含** `allow-same-origin`），因此用户脚本跨源、**无法访问父页/外壳 DOM**。
  - 因跨源无法直接读 `contentDocument`，在注入的 srcdoc 中内置一段**我们自己的桥接脚本**（与用户内容同文档、随 srcdoc 注入）：收到父页 `postMessage('ep:extract')` 后，把 `<!DOCTYPE html>\n' + document.documentElement.outerHTML` 通过 `event.source.postMessage({type:'ep:extracted',html}, '*')` 回传；父页校验 `event.source===预览Frame.contentWindow`。
- **产出文件**：`src/adapters/preview/IFramePreviewSandbox.ts`（替换/完善 T101 最小版）、`src/adapters/preview/bridge.ts`（生成桥接脚本字符串）、`tests/e2e/preview.spec.ts`。
- **实现步骤**：
  1. `open(html)`：把"桥接脚本 + 用户 html"组装进 srcdoc；显示预览帧、隐藏编辑帧；记录编辑帧滚动位置。
  2. 桥接脚本在 DOMContentLoaded 后监听 message；用户脚本正常运行（轮播/表单/按钮）。
  3. `extract()`：向预览帧 postMessage，`Promise` 等待一次 `ep:extracted`（超时 2s 降级：提示无法取回运行态，直接复用编辑 doc，不报错白屏）。
  4. 切回编辑：默认**复用原编辑 doc**（保证撤销历史不失效）；best-effort 把预览中表单 `input/textarea/select` 的当前 value/checked 经 SetAttribute/SetValue 同步回编辑 doc（同步失败不阻断）。恢复滚动（rAF 后 scrollTo）。
  5. 进入预览前若处于就地编辑，先 commit。
- **验收命令**：`npm run e2e`（03-script-carousel：预览轮播播放、可填写点击；切回后改动仍在且 Ctrl+Z 可用；外壳样式不被污染；预览脚本访问 `parent.document` 失败/拿不到 `#ep-app`；预览不产生对外部网络的编辑器请求）。
- **手动验收**：预览效果与直接用浏览器打开该 HTML 一致；反复切换不出现重复 iframe 堆积。
- **不在范围**：多页面预览、响应式断点编辑、把脚本运行后的 DOM 全量替换编辑 doc（仅 best-effort 表单值）。
- **停下求助**：无 same-origin 时桥接 postMessage 被沙箱阻止；srcdoc 中桥脚本与用户脚本冲突。

## T116 · 干净导出序列化（关键质量门）　🟠 / L

- **目标**：导出的 HTML 完全剥离编辑器注入、保留用户原始结构/类/脚本/外链，未编辑部分无损；对未内嵌资源给出清单。
- **依赖**：T101；在 T104/T105/T111/T112 合入后持续回归。
- **开工前读**：`01` §4 `HtmlIO/SerializeResult/EditorArtifact`、§8.3 清理清单、PRD F8。
- **产出文件**：完善 `src/adapters/dom/DomParserIO.ts`、`src/core/serialize/stripArtifacts.ts`、`src/core/serialize/resourceAudit.ts`、`tests/unit/stripArtifacts.test.ts`、`tests/e2e/export.spec.ts`。
- **实现步骤**：
  1. 序列化目标是**编辑 iframe 的 contentDocument**（不是外壳）；输出补 `<!DOCTYPE html>` 与完整 `<html><head>…`。
  2. `stripArtifacts` 逐条落实 §8.3：移除残留 `contenteditable`、`data-ep-editing`/`data-ep-*`、覆盖层/外壳节点、编辑器注入的 `style#ep-*`/`script#ep-*`、临时 class；返回残留清单。
  3. 保留：用户结构、用户 class/id、用户操作产生的内联样式（含 transform 位移、display 隐藏）、用户原始 `<script>` 与外链。
  4. `residue.length>0` → 抛 `EP.IO.RESIDUE` 阻断导出并 toast；正常则触发下载（文件名取页面标题或 `edited.html`）。
  5. `resourceAudit`：列出外链 img/font/script/stylesheet；对 `blob:`/`data:` 中由本地 objectURL 产生的图片明确警告"该图片未内嵌，换电脑/分享会失效（base64 内嵌为 P1）"。
  6. 提供"复制 HTML 到剪贴板"与"下载 .html"两个出口，均过同一清理函数。
- **验收命令**：`npm run test`（每种注入物各一条清理用例 + 保留用例）；`npm run e2e`（导出→新标签打开与预览一致）；`npm run qa:metrics`：**residueCount=0、losslessRate 达基线（未编辑导出与原文件规范化一致）**。
- **手动验收**：对全部样本各导出一次，VS Code 全局搜 `ep-`/`contenteditable` 为 0；含脚本样本导出后脚本仍在并可运行。
- **不在范围**：base64 图片内嵌、CSS 抽离为外部文件、class 写回模式（P1）。
- **停下求助**：清理规则误伤用户合法属性；规范化 diff 出现无法解释的系统性差异。

## T117 · 本地保存与自动草稿　🟢 / M

- **目标**：自动草稿不丢内容；支持 File System Access 直接打开/保存本地文件，不支持的浏览器平滑降级为上传/下载。
- **依赖**：T101。
- **开工前读**：`01` §4 `DraftStorage/LocalFileGateway`、PRD F8。
- **产出文件**：`src/adapters/storage/IdbDraftStorage.ts`（idb）、`src/adapters/storage/FsLocalFileGateway.ts`、`src/core/stores/draft.ts`（防抖自动保存）、`tests/unit/draft.test.ts`、`tests/e2e/persist.spec.ts`。
- **实现步骤**：
  1. 草稿结构 `DraftRecord`（含 `schemaVersion:1`、sourceSnapshot、title、updatedAt）；`markDirty` 后防抖（如 1.5s）保存当前编辑 HTML（导出同款序列化，但允许保留会话态）。
  2. `LocalFileGateway.isSupported` 检测 `showSaveFilePicker/showOpenFilePicker`；支持则打开/保存直连本地 `.html`，**保存前必须二次确认**（防不可逆覆盖，PRD F8）。
  3. 不支持时：打开走 `<input type=file>`，保存走 `<a download>`；UI 明确告知。
  4. Ctrl+S / Ctrl+O 接线（替换 T114 占位）；首次保存需命名。
  5. schemaVersion 读取时校验，未来版本不兼容给出提示而非崩溃。
- **验收命令**：`npm run test`（防抖、版本、CRUD，用 fake-indexeddb）；`npm run e2e`（编辑→刷新→从最近草稿恢复；不支持 API 的环境模拟降级走下载）。
- **手动验收**：意外关闭标签页后重开可恢复；保存不覆盖无确认。
- **不在范围**：云同步、账号、多文件工程。
- **停下求助**：File System Access 在目标浏览器行为与文档不符；idb 容量/隐私模式异常无法降级。

## T118 · 起始页与三种导入 + 容错提示　🟢 / M

- **目标**：正式起始页：上传 / 粘贴 / 空白三入口、最近草稿、导入解析的修复与风险提示。
- **依赖**：T117。
- **产出文件**：`src/app/startpage/StartPage.ts`、`ImportDialog.ts`（粘贴）、`src/core/io/importReport.ts`、`tests/e2e/startpage.spec.ts`。
- **实现步骤**：
  1. 三入口卡片：上传 `.html`（accept html/text）、粘贴代码（大文本框）、新建空白（最小 HTML5 骨架）。
  2. 最近草稿列表（标题/时间：继续、删除、另存）。
  3. 解析后报告（非阻断 toast/面板）：①"含脚本，脚本仅在预览模式运行"；②残缺 HTML"已按浏览器规则自动修复"（能计数则给数量，不能则给定性提示，不编造数字）；③节点数超 `LARGE_PAGE_NODES` 的规模提示；④汇总"N 个元素不支持内部编辑"（数据来自 T119 扫描）。
  4. 错误处理：非 HTML/空内容/读取失败给明确文案与重试，不白屏。
  5. 文件编码异常按 UTF-8 读取并在乱码高风险时提示。
- **验收命令**：`npm run e2e`（三入口、最近草稿续开、05-malformed 不白屏并出提示、空文件报错）。
- **手动验收**：粘贴 AI 生成整页一键进入编辑（核心 Aha 路径 ≤ 数次点击）。
- **不在范围**：URL 导入（P1）、模板市场、拖拽文件到任意位置（可支持拖到起始页，非必须）。
- **停下求助**：容错计数无法可靠实现（退定性提示即可，不要伪造数字）。

## T119 · 安全消毒与可编辑性降级　🟠 / M

- **目标**：落地 §7 能力分级与提示；确认编辑态/预览态隔离安全；提供粘贴净化能力。
- **依赖**：T103、T115。
- **开工前读**：`01` §5、§7、§4 `CapabilityIndex/PasteSanitizer`、PRD F10/F11。
- **产出文件**：`src/core/capabilities/scanner.ts`（纯规则 + 单测）、`src/adapters/sanitize/PasteSanitizer.ts`（按 T003 许可结论选 DOMPurify 或自研白名单）、`tests/unit/capabilities.test.ts`、`tests/e2e/security.spec.ts`。
- **实现步骤**：
  1. scanner 按 §7 输出 full/inline-text/block-only/non-editable 及原因 key：表单控件、`<a>`→inline-text；Shadow 宿主、复杂第三方组件根、canvas/复杂 SVG 容器→block-only；Shadow 内部、canvas 位图、伪元素内容→non-editable。
  2. 非 full 元素：选中时给样式与文案，仅允许整体移动/隐藏/替换；操作不报错、不破坏结构。
  3. 安全 E2E（写一个"恶意样本"）：编辑态脚本不执行（不发请求、不改外壳）；预览态脚本能运行但**访问不到** `parent.document` / `#ep-app` / cookie；编辑器全程无外联请求（用网络监听断言）。
  4. PasteSanitizer：白名单基础标签/样式，去脚本、`on*` 事件属性、Word 专有标签；单测覆盖 `<script>`、`onerror`、`javascript:`  href。P0 就地粘贴仍为纯文本（T104），该 sanitizer 作为能力交付并在"插入富文本/未来入口"接线，不改变 P0 结论。
  5. 导出含用户原始脚本时给一次可信提示（不删除用户代码）。
- **验收命令**：`npm run test`（分级判定、净化攻击向量）；`npm run e2e`（恶意样本隔离断言、block-only 元素整体可移动并出提示）。
- **手动验收**：08-shadowdom、07-svg-table 样本中不可入内元素有明确提示而非无响应。
- **不在范围**：CSP 策略生成、服务端杀毒、多租户权限。
- **停下求助**：发现用户脚本能跨帧访问外壳（隔离失效，**阻断级问题，立即上报停止发布**）。

## T120 · 性能 / 规模、打包发布与许可合规　🟢 / M

- **目标**：大页面可用不卡；产出可静态部署、可灰度回滚的版本；许可清单完整。
- **依赖**：T116、T115、T119（Stage 3 收尾）。
- **产出文件**：`docs/ops/部署与回滚.md`、`docs/plan/依赖清单(SBOM).md`（终版）、`scripts/check-licenses.mjs`、性能用例 `tests/e2e/perf-large-page.spec.ts`、vite 构建配置调整。
- **实现步骤**：
  1. 审计并确保：所有 pointermove/scroll 高频逻辑在 rAF；覆盖层用 transform/opacity 合成；hover 命中在大页采用节流/最近命中缓存；超过 `LARGE_PAGE_NODES` 时关闭实时 hover 高亮等重操作并提示（只读/精简模式）。
  2. 用 09-large 样本度量：导入耗时、拖拽帧率、内存（记录数值，阈值由 T003/评审据实测定，不在本卡编造）；不达标则优化热点后复测。
  3. 构建：相对路径 base、静态资源版本化（hash）、注入构建版本（git sha）；`npm run build` 产物可托管任意静态服务器。
  4. `部署与回滚.md`：灰度（按静态版本引流）、监控前端错误与三大红线（导入崩溃率、导出残留、预览不一致）、回滚=切换静态版本；本地草稿结构向后兼容说明。
  5. `check-licenses.mjs`：校验所有生产依赖许可在白名单（MIT/BSD/Apache/ISC），命中 GPL/AGPL/SSPL/未知则退出非 0；生成 `third-party/LICENSES` 汇总与 NOTICE；接入 `npm run check`。
  6. 跑全量 `npm run check` 与 `npm run qa:metrics`，确认 Stage 3 门禁全部满足，输出最终度量报告。
- **验收命令**：`npm run check`、`npm run e2e`（含 perf）、`npm run qa:metrics`（hitRate/losslessRate 达 T003 设定门槛、residueCount=0）、`node scripts/check-licenses.mjs`。
- **手动验收**：`dist/` 在干净浏览器从静态服务打开，完成一次导入→编辑→预览→导出全流程；断网可用（无外链依赖时）。
- **不在范围**：CI/CD 平台具体配置（可在文档给通用步骤）、监控 SDK 选型、服务端。
- **停下求助**：存在非白名单许可的硬依赖；大页面性能在常规优化后仍不可用（需升级到虚拟化方案，属新决策）。
