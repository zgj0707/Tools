## 2. 设计意图：五层与六条硬约束

```
index.html → src/main.ts → app/（外壳 UI，原生 DOM）
                             ├─→ core/（端口接口 + 纯逻辑，禁第三方、禁 app、禁 adapters）
                             └─→ adapters/（唯一可 import 第三方处）
platforms/web/（装配根：构造适配器并注入 core/app）
```

六条硬约束（契约 §1）：

1. 真实 DOM 是唯一事实源，不引虚拟组件树（对"任意第三方 HTML"是正确的取舍）
2. 被编辑文档与编辑器外壳**物理隔离**（双 iframe）
3. 零污染引用：不往被编辑 DOM 写 `id`/`data-*` 做选中映射
4. 端口 + 适配器（依赖倒置），第三方只出现在 `adapters/`
5. 一切改变文档的操作都走 Command，统一接入撤销/重做
6. 位移只用 `transform:translate`，**禁止** `position:absolute`（即不做"PPT 画布"）

## 4. 偏差清单（按严重度）

### 4.1 🔴 装配根错位，依赖倒置只剩形式

- 契约 §4 要求：`platforms/web/composition.ts` 构造适配器并注入 `App`/`EditorSession`；"`app/` 与 `core/` 不 `new` 具体适配器"。
- 实际：`createApp()` 定义在 `app/App.ts:884-889`，并且 `App.ts:17-19` 直接
  `import { DomParserIO } from '../adapters/dom/DomParserIO'`、
  `IFramePreviewSandbox`、`SelfInteractionAdapter`。
- 后果：
  1. 换解析器 / 换预览实现 / 换交互实现，**必须改 `App.ts`**——端口抽象的成本已经付了，收益没拿到。
  2. `app/` 无法在 happy-dom 之外做纯逻辑单测，`App.ts` 成为不可测的 889 行巨物（20 个私有字段、40+ 方法，装进了导入导出、拖拽、缩放、对齐、图层、快捷键、预览、草稿）。
  3. ESLint 边界规则也没兜住：`.eslintrc.cjs:29-45` 只配了 `core → app/adapters` 方向的 `import/no-restricted-paths`，**`app → adapters` 方向没有任何约束**，且文档 §3 承诺的"app 只允许 import core"没有对应规则。

### 4.2 🔴 质量门禁的"无损率"是构造性结论

`qa/metrics/run-metrics.mjs:166-168`：

```js
// 编辑前 = 编辑后 = 同一文件（Stage 0：编辑器未接入）。
const beforeDoc = parser.parseFromString(afterHtml, 'text/html');
const afterDoc  = parser.parseFromString(afterHtml, 'text/html');
```

- 拿同一段字符串解析两次再 diff，`losslessRate` **必然 = 1**，这不是"无损"的证据，只是"解析器确定性"的证据。`qa/report/metrics-latest.json` 里 10 个样本全 1.0000 即来源于此。
- `hitRate` 固定 `null`（`run-metrics.mjs:53,193`），`previewConsistency` 至今不存在。
- 契约 §8.2 自己承诺"Playwright 操作级度量待 T101 后升级"——**T101 已完成（walking-skeleton e2e 已通过），升级未发生**。
- 严重性在于流程依赖它：`README-执行指南.md` 铁律 4/5 与 `00-任务规划总览.md §5` 都写着"每卡 `qa:metrics` 不得劣于基线、残留必须为 0"。其中**只有残留检测（六条正则）是真有效的**，另外两项是空转。这意味着过去若干张卡的"未劣化"结论没有证据支撑。

**附带的口径漂移风险**：残留检测有两套实现且口径不同——Node 侧是 6 条正则（`run-metrics.mjs:44-51`），浏览器侧是 DOM 遍历（`stripArtifacts.ts:51-85`）。两者会随清理规则演进而分叉，届时就出现"导出说干净、度量说脏"。

### 4.4 🟠 CapabilityScanner 未达契约 §7

契约 §7 定义四级（`full` / `inline-text` / `block-only` / `non-editable`），并要求"导入后扫描一次 + 结构变更增量更新"，`reasonOf()` 给用户原因文案、"不静默失败"。

实际（`core/model/EditorSession.ts:15-31`）是两张 tag 黑白名单：`script/style/meta/...→non-editable`、`canvas/svg/iframe/video/audio→block-only`，其余一律 `full`。

- 缺 `inline-text` 级；缺 Shadow DOM 内部 / 伪元素 / canvas 位图内部的判定（**而这恰是 §7 举例的真实场景**）；

判定过宽的直接后果：用户对一个 `<a>`、表单控件、或第三方组件根元素点进去改文本，会改出副作用。

## 5. 两个可以复现的具体缺陷

1. **单击缩放手柄不拖动，会把元素尺寸固化成 inline px 并写入历史。**
   `App.ts:653-666` 的 `up()` **无条件** `push(new ResizeCommand(...))`；`ResizeCommand.execute()`（`commands.ts:67`）写 `${Math.round(cur.width)}px`。
   即：用户点一下手柄（甚至手滑），元素就从 `width:auto` 变成固定 px，且占用一步撤销。拖拽路径有 `if (moved)` 保护（`SelfInteractionAdapter.ts:231`），缩放路径漏了。`HistoryStack` 的去空逻辑只识别 `SetTextCommand`（`HistoryStack.ts:14-18`）。
2. **度量与清理口径双实现**（§4.2 末段）——正则 vs DOM，长期必然分叉。

## 6. 值得保留的设计优点（不是客套）

1. **双 iframe 安全矩阵的实现与文档逐字一致**，且给了明确的降级路径（预览帧不给 `allow-same-origin`，用注入桥接 + `event.source` 校验 + 2s 超时换 `null`）。这是本产品最难也最容易被做歪的地方，做对了。
2. **`ADR-002` 是"诚实工程"的范本**：写明跨 realm 真实 `pointermove` 失效的实证、**明确承认未走 Moveable 官方 `iframeManager` 路径**、给出体积对比（gzip ~91 kB → 25.91 kB），并写下"若需复杂手势须先做限时 PoC"的重新引入前置条件。这种 ADR 比选型结论本身更值钱。
3. **core 零第三方依赖 + 纯函数可测**：命令、吸附、对齐、清理、`dragIntent`、`resizeGuard` 都在 core 且有单测，166 个测试全绿，`strict` 全开不用 `any`/`ts-ignore`。这套地基能承受后续重构。
4. **导出安全是"阻断式"而非"提醒式"**：残留非空即抛错，不给用户产出脏文件的可能。
