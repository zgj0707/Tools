## 0. 结论先行

用户反馈「预览、编辑虽然有功能但非常不方便」。实测之后，这个判断**偏温和**——
不是不方便，是三条链路各断一处，其中一条（预览）本质上是**打不开**：

| 链路 | 实测结论 | 严重度 |
|---|---|---|
| **预览** | 点击「预览」后画布被隐藏，而预览帧被渲染在**视口下方 600px 处**（页面总高 1500 > 视口 900）。用户看到的是**一整屏空白**，必须滚动才能看到预览内容 | **P0 · 功能级失效** |
| **编辑（改样式）** | 右侧面板 30 个字段排成一列、总高 1221px，1440 视口下要滚动 45%、1280 视口下要滚动 65%；且**双击进文字编辑时整个面板被清空禁用** | **P0** |
| **编辑（看画布）** | 面板展开后画布只剩 **768px**（1280 视口下 608px），而全站**没有任何缩放能力**兜住 | **P0** |

对标 Figma / Canva，本品缺的不是「细节打磨」，而是**三个基础机制**：
**缩放**、**上下文工具条**、**属性面板分组**。补齐这三项，其余问题大半自解。

## 3. 目标骨架

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ ① 顶栏  [文件▾]  [撤销][重做]  │  [预览▶][面板开关]     文档名 · 未保存●  [导出] │
├────────┬────────────────────────────────────────────────┬────────────────────┤
│ ② 左栏 │  ③ 画布工作区                                    │  ④ 属性面板         │
│        │   ┌──────────────────────────────────────────┐  │  ▸ 文字  (默认展开)  │
│ Tab:   │   │  浮动上下文工具条（选中时出现，贴选中框）    │  │  ▸ 布局              │
│ 插入   │   ├──────────────────────────────────────────┤  │  ▸ 外观  (折叠)      │
│ 图层   │   │                                          │  │  ▸ 尺寸与位置 (折叠)  │
│ 页面   │   │      被编辑页面（可缩放 · 自适应高度）      │  │                    │
│        │   │      · 尺寸徽标 W×H                       │  │  ── 盒模型图形控件 ── │
│        │   │      · 间距标注 / 吸附线                    │  │  ┌───┬───┬───┐     │
│        │   │                                          │  │  │   │ ↕ │   │     │
│        │   └──────────────────────────────────────────┘  │  ├───┼───┼───┤     │
│        │   ⑤ 状态栏：面包屑 · 元素类型 · 尺寸 · 选中数        │  └───┴───┴───┘     │
│        │                                    [− 100% +] ⛶  │                    │
└────────┴────────────────────────────────────────────────┴────────────────────┘
                                          ↑ 缩放控件（右下角，M1）
```

**四条设计原则**

1. **手不离画布**：高频动作贴选中元素浮动（M2），而不是固定在一侧面板。
2. **按需显形**：面板分组默认只展开与当前选中相关的组（M3）；收纳不等于删除。
3. **画布是主角**：画布自适应可用空间且可缩放（M1/M8），面板永不让画布失去可读宽度。
4. **保留 C 版气质**：仍走「极简留白纸感、全站单一蓝色强调色、界面存在感最低」，**不推翻已落地的 token 体系**，只补机制。

### 10.1 五个在实施中才暴露的缺陷（均已修）

| # | 缺陷 | 根因 | 修法 |
|---|---|---|---|
| ① | 点「预览」一屏空白 | `.ep-preview-host` 是死 CSS（建 div 时从未赋 className）；预览宿主排在 `.ep-main` 之后而前者撑满视高 ⇒ 帧从 y=900 起渲染，可见高度 0 | 改全屏覆盖层，并从顶栏下方铺开 |
| ② | 画布只有 608×**152**，下方白留 418px | 🔴 两个 flex 容器的交叉轴写成 `align-items: flex-start`。`.ep-main` / `.ep-canvas-row` 都是**横向**容器，「高度」属交叉轴，与 `flex:1`（管宽度）无关 ⇒ 高度链断掉 ⇒ `height:100%` 落到 auto 父级按规范视为 auto ⇒ **iframe 固有高度 150px** | 两处改 `stretch`；三块侧边面板用 `align-self:flex-start` 显式退出拉伸 |
| ③ | 点一下元素，整块画布上跳 44px | 工具条带是 `flex-wrap` 的；上下文工具条提示文案从「未选中任何元素」变「h2」使工具条缩水约 60px，在容器宽 608px 这一档正好跨过换行临界点 ⇒ 工具条 82px 塌回 38px。**连带把双击改字打坏**：两次 mousedown 落在不同元素上 | `.ep-ctxbar__hint` 定宽 88px + 省略号（完整值挂 `title`） |
| ④ | 刚点开预览「点关关不掉」 | `previewOpen` 在帧 `load` 完的 then 里才置 true，而覆盖层已同步可见 ⇒ 第二次点击读到 false，又走一遍打开分支 | 状态与覆盖层**同步**翻转；Esc 分支改判覆盖层自身状态 |
| ⑤ | 框选矩形偏离指针 | `onBlankDown` 起点多减了一次 `frameRect.left`（覆盖层与画布同位置） | 重写为 `frameRect.left + clientX*z − origin.left`（此前无用例覆盖） |

### 10.4 度量口径的同步（`qa:metrics`）

批次 1 落地后 `npm run qa:metrics` **一度 hitRate 从 1 掉到 0**，10 个样本全部报「缩放失败」。
根因不是产品回归，而是**度量口径少了一条前置**：固定操作脚本里有一句「拖 se 手柄 (+40, +0)」，
它是**屏幕像素**增量，而元素宽高是 **iframe 内部像素**，R2 引入缩放后两者差一个缩放比；
度量脚本只预置了 `easypage:layout`（面板展开），没预置 `easypage:view`，
于是 autoFit 默认开启、zoom≈0.5，「拖 40px」变成「长 80px」。

已补 `VIEW_PRESET`（与 `playwright.config.ts`、`src/app/ui/ViewPrefs.ts` 的 `VIEW_E2E_PRESET` 同值），
三处保持一致。**教训**：凡是「用固定坐标驱动真实 UI 的回归工具」，都必须把
「画布缩放比」声明成显式前置 —— 否则它就是一个隐式的、会随窗口尺寸漂移的变量。
