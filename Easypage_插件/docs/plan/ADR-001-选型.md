# ADR-001 · 开源选型与技术路线（T002 结论，供 T003 冻结）

- 状态：已评审（主代理据 PoC 实证 + 许可复核），待 T003 冻结进 `01-技术基线与接口契约.md`
- 日期：2026-09-21
- 关联：PRD v0.2 D4（优先整合宽松许可开源做适配、核心缺口自研）、D6（闭源，仅宽松许可依赖）

## 1. 背景与决策原则

产品核心是"对**已有/AI 生成的任意第三方 HTML** 做最后一公里可视化精修，并**无损导出**干净 HTML"。因此一条硬约束是：

> **真实 DOM 为唯一事实源**。任何把 HTML 转成自有文档/组件模型、再序列化回写的库，都会引入"模型→HTML"的二次生成，天然污染导出（注入编辑器标记、丢原始属性/注释/事件），与"无损"目标冲突。

据此把候选分两类：
- **A 类：纯交互/工具库**（不接管 DOM 模型，只提供指针、变换、净化、存储能力）——可整合，关进 `src/adapters`。
- **B 类：自带文档/组件模型的整页编辑器**（GrapesJS、Tiptap、Lexical 等）——会再做一次 DOM 模型转换，原则上**不整合**。

## 2. 逐项结论

| 候选 | 许可 | 结论 | 理由 |
| --- | --- | --- | --- |
| **GrapesJS** | BSD-3（宽松✓） | **不整合** | 它把 HTML 解析成自有 Component Model，`getHtml()` 会注入 `gjs-*` 标记、倾向丢弃自定义 `data-*`/注释/内联事件（probe 设计的三个证伪点正针对此）。PoC 实证：在 jsdom 无头环境 `grapesjs.init()` 挂起、>3 分钟无任何 stdout（已中止），自动化/CI 成本高。方向证伪：我们走"真实 DOM + 端口适配器"轻量内核。 |
| **Moveable** | MIT（✓） | **采用（首选）** → 已被 ADR-002 取代（移除） | 纯指针/变换库，只负责选中框、8 向手柄、拖拽缩放的指针交互，**不接管 DOM、不写编辑器标记、不强制 absolute**；与我们"`transform:translate` 位移、保留文档流"模型吻合。**注：T105 实证其在"target 在编辑 iframe 内、控制器在外壳"的跨 realm 结构下真实鼠标拖拽不可靠，且仅用于画框即把 gzip 推到 ~91kb；已于 Stage 2 第 0 步按 ADR-002 整体移除，交互全自研。本行保留历史不删。** |
| **interact.js** | MIT（✓） | 备选 | 能力可替代 Moveable，API 较老；若 Moveable 集成不顺则回退。 |
| **就地编辑：自研 contentEditable 收敛** | 自研（无许可问题） | **P0 采用** | 契约已规定：双击按需激活、Enter/Esc/blur 行为统一、提交即清标记、粘贴纯文本。 |
| **Tiptap / Lexical** | MIT（✓） | **P0 不采用** | 二者都把文本转成 ProseMirror / Lexical 树，又是一层 DOM 模型转换，破坏无损导出。P0 就地编辑只改文本节点，自研足够；富文本结构化编辑属后续。 |
| **DOMPurify** | MPL-2.0 / Apache-2.0 双许可 | **采用（按 Apache-2.0 路径）** | 仅用于 `PasteSanitizer`（粘贴片段净化），**不用于导入**（导入必须保留 `<script>` 到预览态运行）。MPL-2.0 为文件级弱 copyleft：不改其源码、仅作为独立库引用时可闭源分发；DOMPurify 提供 Apache-2.0 许可分支，按 Apache-2.0 采用并在 NOTICE 记录。 |
| **parse5** | MIT（✓） | 采用（兜底） | 主解析用浏览器 `DOMParser`（真实 DOM 事实源）；parse5 作为容错/规范化校验的兜底工具，已在依赖。 |
| **idb** | ISC（✓） | 采用 | `DraftStorage` 草稿存储。 |
| **Playwright / Vitest / happy-dom / Vite / ESLint / Prettier / TypeScript** | Apache-2.0 / MIT / ISC | 采用 | 测试与构建链，均宽松许可。 |

## 3. 最终技术路线（一句话）

**真实 DOM 为唯一事实源；外壳原生 TS+DOM（不引 React/Vue）；交互用 Moveable 关进 `InteractionAdapter`；就地编辑自研 contentEditable 收敛；粘贴净化用 DOMPurify（Apache 路径）；草稿用 idb；不引入任何"整页编辑器/文档模型"型库。**

## 4. 许可白名单（T003/SBOM 据此校验）

允许：MIT、BSD-2/3-Clause、Apache-2.0、ISC、CC0。
禁止进入生产依赖：GPL、LGPL（动态链接仍需评估）、AGPL、SSPL、MPL-2.0（除非按 Apache-2.0 分支采用且不改源码）、未知许可。
> 注：DOMPurify 双许可，采用时按 Apache-2.0 分支并在 `third-party/NOTICE.md` 写明；不修改其源码。

## 5. 后果与待 T003 冻结点

- 正面：无第二个 DOM 模型转换层，"无损导出任意第三方 HTML"目标可达；依赖面小、许可干净。
- 代价：选中框/手柄/吸附等交互需围绕 Moveable 适配，而非开箱即用；复杂组件模型（如 GrapesJS 的区块库）我们不做，符合 P0 范围。
- **T003 需据此冻结**：
  1. `InteractionAdapter` 的实现选 Moveable（版本号、API 封装边界写进 `01`）；
  2. `PasteSanitizer` 基于 DOMPurify，白名单与"不用于导入"写死；
  3. `SessionMeta` 等 `ports.ts` 中的占位类型补全为正式形状；
  4. SBOM/脚本 `check-licenses` 按 §4 白名单实现；
  5. 记录：GrapesJS/Tiptap/Lexical 的否决理由存档于本 ADR，未来不再重复选型。
